# Using Jilt Builder over Lombok

Example of creating records with a **staged builder** generated by [Jilt](https://github.com/skinny85/jilt), with nullability checked at compile time by [JSpecify](https://jspecify.dev/) + [NullAway](https://github.com/uber/NullAway).

## Why Jilt instead of Lombok `@Builder`?

A classic builder (e.g. Lombok) can be finished with `build()` at any time. Forget a field and you silently get `null` – or, for a `boolean`, a `false` that is indistinguishable from a deliberately set `false`.

Jilt with `BuilderStyle.STAGED` instead generates a separate stage (interface) for every required attribute. `build()` only becomes reachable once **all** required attributes are set – including the `boolean`s:

```java
UserAccountBuilder.userAccount()
    .id(UUID.randomUUID())
    .username(username)
    .email(email)
    .firstName(firstName)
    .lastName(lastName)
    .active(true)
    .emailVerified(false)   // omit it → compile error
    .createdAt(clock.instant())
    .phoneNumber(phoneNumber) // @Nullable → optional
    .build();
```

If you leave out e.g. `.emailVerified(false)`, the build fails with `cannot find symbol`, because the `EmailVerified` stage offers no `createdAt(...)` method.

Jilt automatically treats attributes annotated with JSpecify `@Nullable` as optional. They are set at the end of the chain and may be omitted.

## Null safety with JSpecify and NullAway

The [`nullability-maven-plugin`](https://github.com/making/nullability-maven-plugin) does all the wiring:

- Goal `configure` sets up Error Prone and NullAway (in JSpecify mode) in the `maven-compiler-plugin`. Only production
  code (`src/main`) is checked.
- Goal `generate-package-info` generates a `package-info.java` annotated with `@NullMarked` for every package into
  `target/generated-sources/nullability`. So there is no hand-written `package-info.java`, yet everything is non-null
  unless explicitly marked `@Nullable`.

Example: passing `null` to a non-null builder step, e.g. `.createdAt(null)`, fails compilation with

```
[NullAway] passing @Nullable parameter 'null' where @NonNull is required
```

## Structure

| File                     | Content                                                                                                                    |
|--------------------------|----------------------------------------------------------------------------------------------------------------------------|
| `UserAccount`            | Record with 10 attributes, 2 of them `@Nullable` (`phoneNumber`, `lastLoginAt`), annotated with `@Builder(style = STAGED)` |
| `UserAccountService`     | Creates a `UserAccount` via the generated `UserAccountBuilder`                                                             |
| `UserAccountServiceTest` | JUnit Jupiter (JUnit 6) + AssertJ                                                                                          |

The builder is generated into `target/generated-sources/annotations` at compile time. Jilt is only needed at compile time (`provided`) and is registered explicitly as an `annotationProcessorPath` in the `maven-compiler-plugin`, because since JDK 23 annotation processors are no longer picked up from the classpath automatically.

Since Error Prone requires a forked `javac`, the compiler locale is forced to English via `-J-Duser.language=en` so that
compiler messages are English regardless of the OS locale.

## Requirements and build

- JDK 25
- Maven 3.9+ – the `nullability-maven-plugin` silently does nothing on older versions (e.g. 3.6.x). That's why a Maven Wrapper (3.9.16) is included.

```bash
./mvnw verify
```
